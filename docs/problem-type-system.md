# problem-type-system.md

# Problem Type System

## Overview

The platform supports multiple categories of mathematical problems.

Each problem type requires different validation strategies and learning flows.

This document defines the **problem type system** used by:

- Practice Engine
- Problem Generator
- Step Validation Engine
- AI Tutor
- Curriculum Engine

The goal is to ensure that:

- each problem is validated correctly
- the appropriate validator is used
- difficulty scaling is consistent

---

# Problem Sources

Problems can originate from multiple sources.

Sources:

```
template
llm_generated
material_extracted
```

Descriptions:

| Source | Description |
|------|------|
| template | generated from symbolic templates |
| llm_generated | generated by LLM for olympiad-style reasoning |
| material_extracted | extracted from uploaded books or notes |

---

# Problem Categories

Problems are classified by **mathematical structure**.

Categories:

```
algebra_equation
algebra_expression
system_of_equations
calculus_derivative
calculus_integral
functional_equation
number_theory
proof_problem
```

Example mapping:

| Problem | Category |
|------|------|
| 7x + 3 = 31 | algebra_equation |
| 2(x+3) simplify | algebra_expression |
| x+y=5, x−y=1 | system_of_equations |
| d/dx(x²+3x) | calculus_derivative |
| ∫2x dx | calculus_integral |
| f(x² + f(y)) = y + f(x)² | functional_equation |

---

# Validation Strategy

Each problem category determines the **validator type**.

| Problem Type | Validator |
|------|------|
| algebra_expression | symbolic |
| algebra_equation | symbolic |
| system_of_equations | symbolic |
| calculus_derivative | symbolic |
| calculus_integral | symbolic |
| functional_equation | reasoning |
| number_theory | reasoning |
| proof_problem | reasoning |

Validator types:

```
symbolic
reasoning
hybrid
```

Descriptions:

Symbolic validator:

```
SymPy
CortexJS
```

Reasoning validator:

```
LLM reasoning validator
```

Hybrid validator:

```
symbolic validation
+
LLM reasoning validation
```

---

# Step Validation Routing

When a student submits a step, the system determines which validator to use.

Flow:

```
Student Step
↓
Step Validation Engine
↓
retrieve problem_type
↓
route to correct validator
```

Example:

```
problem_type = algebra_equation
→ symbolic validator
```

Example:

```
problem_type = functional_equation
→ reasoning validator
```

Example:

```
problem_type = olympiad_algebra
→ hybrid validator
```

# Difficulty System

Difficulty is independent from problem type.

Difficulty scale:

```
1 → beginner
2 → basic
3 → intermediate
4 → advanced
5 → olympiad
```

Example:

| Problem | Difficulty |
|------|------|
| 7x+3=31 | 1 |
| quadratic equations | 2 |
| system of equations | 3 |
| derivatives | 4 |
| functional equations | 5 |

# Curriculum Integration

The Curriculum Engine uses problem types to control learning progression.

Example learning path:

```
linear equations
↓
polynomials
↓
systems of equations
↓
derivatives
↓
olympiad problems
```

This ensures students develop prerequisite skills before advanced reasoning problems.

The Problem Type System ensures that:
